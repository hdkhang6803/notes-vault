# 1. Terminology

| Term                                                 | Definition                                                                                                                                                                                                                                                                                                                                                                                       |
| ---------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| POMDP (Partially Observable Markov Decision Process) | A tuple (S, A, T, R, Ω, O, γ) extending an MDP so that the agent only receives observations o ∈ Ω generated by O(o\|s,a) rather than the true state s, forcing the policy π(·\|o_{1:t}) to condition on the observation history.                                                                                                                                                                 |
| Correlation horizon (ξ)                              | A scalar ξ > 1 defined as the minimum number of timesteps between an event critical for a decision and the later timestep at which that information must be recalled; a task is "memory-intensive" precisely when such a ξ exists.                                                                                                                                                               |
| Object Memory                                        | One of four taxonomy classes covering tasks that require tracking object-related properties (identity, color, shape) across periods of occlusion, aligned with the cognitive-science concept of object permanence.                                                                                                                                                                               |
| Spatial Memory                                       | Taxonomy class covering tasks requiring an agent to remember object/location coordinates or maintain a mental map of the environment layout after those locations are no longer directly observable.                                                                                                                                                                                             |
| Sequential Memory                                    | Taxonomy class covering tasks requiring an agent to store and reproduce temporally ordered information (e.g., an exact sequence of items) analogous to human serial recall.                                                                                                                                                                                                                      |
| Memory Capacity                                      | Taxonomy class covering tasks that stress how many discrete pieces of information an agent can retain and act on simultaneously, analogous to human memory span.                                                                                                                                                                                                                                 |
| MIKASA-Base                                          | A Gymnasium-compatible aggregation of pre-existing open-source memory-intensive RL environments (e.g., POPGym, Minigrid-Memory, Memory Maze), unified under one API and classified into the four taxonomy categories.                                                                                                                                                                            |
| MIKASA-Robo                                          | A GPU-parallelized suite of 32 tabletop robotic manipulation tasks across 12 categories, built on ManiSkill3, in which each task isolates one or more of the four memory types.                                                                                                                                                                                                                  |
| TCP (Tool Center Point)                              | The 6-DoF pose (position + rotation) of the robot gripper's reference point, included in the `joints` and `state` observation modes as part of proprioceptive input.                                                                                                                                                                                                                             |
| Observation modes                                    | Five interchangeable input configurations exposed by every MIKASA-Robo task:<br>- `state` (full oracle vector, MDP setting), <br>- `RGB` (two camera views only)<br>- `joints` (TCP pose + joint states)<br>- `RGB+joints` (the designated standard memory-testing configuration),<br>- `oracle` (task-specific debug data),<br>- `prompt` (static task instruction, used only in Rotate tasks). |
| Oracle Info                                          | A task-specific ground-truth scalar or vector (e.g., `cup_with_ball_number`, `initial_velocity`, `y_angle_diff`) that the agent must implicitly reconstruct from memory to solve the task; listed per task in Table 1 of the paper.                                                                                                                                                              |
| ManiSkill3                                           | The underlying GPU-parallelized robotics simulation and rendering framework (Tao et al., 2024) on which MIKASA-Robo is built, providing efficient parallel training.                                                                                                                                                                                                                             |
| RATE (Recurrent Action Transformer with Memory)      | A Transformer-based offline-RL sequence model with an explicit memory mechanism (Cherepanov et al., 2024b), used as the primary memory-enhanced offline baseline.                                                                                                                                                                                                                                |
| DT (Decision Transformer)                            | A Transformer-based offline-RL baseline (Chen et al., 2021) that predicts actions conditioned on return-to-go and trajectory history, used without an explicit memory module in this paper's comparisons.                                                                                                                                                                                        |

# 3. What it measures (What)

## 3.1 Task definition

Each MIKASA-Robo task is a POMDP with a correlation horizon ξ > 1 (ξ measures _how far back_ the agent has to reach into its history to solve the task): the agent observes some memory-relevant cue (an object's location, color, shape, velocity, or a sequence of cues), the cue then becomes unobservable (occluded, removed, or time-delayed), and the agent must act correctly on the reconstructed information after the delay.
Every task is explicitly **designed to isolate one (or a controlled combination) of the four taxonomy classes — Object, Spatial, Sequential, Memory Capacity — so that failures can be attributed to a specific memory competency** rather than to confounds like perception, clutter, or long-horizon credit assignment. 
Complexity is scaled within each task family via explicit modes (interaction type, number of distractors, velocity, sequence length) rather than by changing the underlying memory mechanism being tested.

## 3.2 Example Records

Running example — **ShellGameTouch-v0** (Object Memory, mode `Touch`):

- **Observation Phase** (steps 0–4): a red ball is shown at one of three positions on the table.
- **Occlusion Phase** (step 5): three identical mugs cover all three positions, hiding the ball.
- **Action Phase** (steps 6+, timeout T = 90): the agent must touch the mug that covers the ball; success requires gripper contact with the correct mug for ≥0.1 s.
- **Oracle Info** field: `cup_with_ball_number` (ground-truth index of the correct mug, used for dataset generation and debugging, not given to the memory-testing agent).
- **Dense reward** combines gripper-to-target-mug distance, joint-velocity smoothness, and a task-completion bonus; **sparse reward** is a binary 1.0/0.0 success flag.
- A corresponding offline-RL dataset record for this task stores, per trajectory: `rgb` (two 128×128 camera frames per step), `joints` (TCP + joint state/velocity, 25-dim), `action` (8-dim), `reward`, `success`, and `done`.

## 3.3 Metrics

|Metric|Definition|Used for|
|---|---|---|
|Success Rate (SR)|Fraction of evaluation episodes in which the task's binary success condition is met|Online RL (PPO-MLP/LSTM, SAC, TD-MPC2), offline RL, VLA baselines|
|Return|Cumulative (typically dense) reward per episode|Online RL training curves (e.g., Figure 5, RememberColor)|
|Mean ± SEM|Success rate/return averaged over 3 independent training runs, each evaluated on 16 (simulated) or 100 (offline/VLA/real-world) episodes, reported as mean ± standard error of the mean|All quantitative result tables|
|Touch / Pick success (real-world only)|Binary flags for whether the robot physically contacted (`is_touched`) or successfully grasped (`is_picked`) the correct real-world cube|Real-world SO-101 experiments (Table 10)|

## 4.2 Uniqueness (concise)

MIKASA is, per the authors, the first benchmark to:
1. supply an explicit four-category cognitive-science-grounded taxonomy for classifying _any_ memory-intensive RL task, 
2. unify heterogeneous existing memory-RL environments under one Gym-like API (MIKASA-Base) rather than leaving evaluation fragmented across bespoke environments
3. instantiate that taxonomy as 32 _atomic_, GPU-parallelized, low-level-control robotic manipulation tasks (MIKASA-Robo) — a combination no prior robotics framework offers (Table 3). It further distinguishes itself by pairing simulation results with online RL, offline RL, and VLA baselines, released expert datasets for all 32 tasks, and physical-robot (SO-101) validation isolating memory as the dominant real-world failure mode rather than embodiment or perception noise.

# 5. Generation Method (How)

MIKASA-Robo tasks are generated and evaluated through a consistent three-phase template, illustrated with the running **ShellGameTouch-v0** example:

1. **Task instantiation (System/scene structure).**
    
    - Each task is registered as a ManiSkill3 environment (`@register_env`) subclassing a base task class (e.g., `ShellGameTouchEnv`), which exposes tunable class attributes controlling difficulty (e.g., `BALL_RADIUS`, `MIN_DIST`, `TIME_OFFSET`, `GOAL_THRESH`).
     > _Example:_ `ShellGameTouchDebug-v0` sets `TIME_OFFSET = 5` (ball visible for 5 steps) and `GOAL_THRESH = 0.08` (contact tolerance), then is created via `gym.make("ShellGameTouchDebug-v0", num_envs=256, obs_mode="rgb", render_mode="all")`.
        
    - Objects are deliberately kept as primitive shapes (cubes, spheres, pegs) to isolate memory from perception/contact confounds; complex meshes (YCB, BridgeData V2) and clutter are supported as optional extensions once the atomic task is solved.
2. **Cue presentation and occlusion (Retrieval-relevant structure).**
    
    > _Example (continued):_ At steps 0–4 the ball's position is directly observable (Observation Phase). At step 5, three mugs simultaneously cover all candidate positions (Occlusion Phase), removing the memory-relevant signal from the observation stream.
        
    - This phase structure (visible cue → occlusion/delay → decision) is the shared generative pattern across all 32 tasks, with phase lengths, number of distractors, or motion parameters varied per task family (`RememberColor`'s `DELTA_TIME`, `Intercept`'s `VELOCITY_RANGE`, `SeqOfColors`'s `SEQUENCE_LENGTH`/`STEP_DURATION`, etc.).
3. **Action / decision and reward computation (Updating flow → evaluation).**
    
     > _Example (continued):_ From step 6 onward (Action Phase) the agent must interact with the mug it inferred to be correct. Success is a binary contact/push/lift condition depending on mode (`Touch`/`Push`/`Pick`); dense reward additionally shapes gripper-to-target distance and motion smoothness.
        
    - Multiple observation modes (`state`, `RGB`, `joints`, `RGB+joints`, `oracle`, `prompt`) are computed simultaneously and exposed through wrappers (`StateOnlyTensorToDictWrapper`, `RenderStepInfoWrapper`, task-specific info wrappers), so the same underlying simulation can serve MDP validation (`state`) or memory evaluation (`RGB+joints`) without regenerating the task.
    - Offline datasets are generated by rolling out a `state`-mode PPO-MLP agent trained to 100% SR with sparse rewards, recording 1,000 successful trajectories per task with synchronized RGB, joint, action, reward, and success fields — the same generation pipeline is reused for all 32 tasks, only the task class differs.
    - Real-world data (SO-101 arm) follows the identical three-phase logic physically staged across three complexity tiers (Task 1: no occlusion; Task 2: dynamic but non-occluded; Task 3: full occlusion + permutation) to isolate memory as the causal variable outside simulation.

# 6. Gaps

- **Restricted problem scope (author-stated):** the benchmark's tasks are confined to single-episode POMDPs; higher-level phenomena such as meta-RL (reasoning over distributions of tasks rather than isolated trajectories) fall outside the current POMDP-based formulation.
- **No modeling of memory failure dynamics (author-stated):** spurious correlations, interference between stored representations, and memory overwriting/forgetting under limited capacity are explicitly identified as unexplored.
- **Metric limitation (author-stated):** evaluation relies solely on success rate/return; the authors call for additional metrics that could more precisely and discriminatively assess _how_ an agent's memory mechanism fails, not just whether the episode succeeds.
- **Limited VLA adaptation depth (author-stated):** the VLA experiments fine-tune only lightweight components (e.g., readout heads for Octo, LoRA adapters for OpenVLA) rather than exploring more extensive large-VLA adaptation strategies within MIKASA.
- **(Claude-proposed) Clutter and realistic object variation are optional add-ons, not part of the core atomic suite** — this design choice cleanly isolates memory but means the 32 official tasks may still understate the difficulty agents would face when memory demands co-occur with cluttered, contact-rich scenes, a combination the paper does not benchmark by default.
- **(Claude-proposed) Real-world validation is narrow in scope** — the physical experiments cover only the `RememberColor3` family (3 cubes, one memory type, one embodiment/model pairing: SO-101 + fine-tuned π0.5), so the claim that "memory, rather than embodiment or perception noise, is the primary limitation" is demonstrated for one task category rather than across the taxonomy's full range (e.g., no real-world Sequential or Memory-Capacity validation).

# 7. Highlights

### Online RL Baselines

|Approach|Architecture & How It Works|Memory Mechanism|Role / Results in Paper|
|---|---|---|---|
|**PPO-MLP**|Proximal Policy Optimization: an on-policy actor-critic method that collects rollouts, then updates the policy with a clipped surrogate objective that keeps new and old policy ratios within a trust region, avoiding destructively large updates. The actor and critic are both simple feedforward MLPs that map the _current_ observation directly to an action/value — there is no mechanism to look back at past observations.|None. Each decision depends only on the current timestep's observation.|Memory-less baseline. Achieves 100% SR in `state` mode (full oracle info given every step, so no memory is actually needed), confirming the tasks are solvable and well-posed. Collapses in `RGB+joints` mode once information must be recalled from earlier steps.|
|**PPO-LSTM**|Same PPO training loop as above, but the actor/critic networks include an LSTM layer between the encoder and output heads. At each step the LSTM updates a hidden state (and cell state) as a function of the new observation _and_ the previous hidden state, via input/forget/output gates that control what old information is kept, discarded, or overwritten. The hidden state carries forward across the episode (reset at episode boundaries), so the policy's action can depend on the entire observation history compressed into that fixed-size vector.|Explicit, via recurrent hidden state (gated recurrence).|Memory-enhanced counterpart to PPO-MLP. Outperforms it on easy cases (e.g., 3-color RememberColor) by using the hidden state to retain the cue after occlusion, but the fixed-capacity hidden state increasingly loses information as the number of distractors/timesteps grows, so success collapses on 5–9 color variants and under sparse reward.|
|**SAC-MLP**|Soft Actor-Critic: an off-policy, maximum-entropy actor-critic algorithm. It trains a stochastic policy and two Q-function critics using a replay buffer, and adds an entropy bonus to the objective so the policy is encouraged to stay stochastic/exploratory rather than collapsing prematurely. The temperature coefficient weighting the entropy term is itself learned. Networks are plain MLPs operating on the current observation only.|None. Off-policy sample reuse improves data efficiency, but there is nothing that aggregates information across timesteps.|Popular robotics baseline chosen for its typically strong sample efficiency. Learns faster than PPO-MLP early on, but — lacking any memory — fails identically to PPO-MLP once the task requires bridging an occlusion gap.|
|**TD-MPC2**|A model-based method that learns a latent world model (encoder → latent state, plus learned latent dynamics, reward, and value functions) purely from replayed transitions, then plans actions at execution time using Model Predictive Control: it samples/optimizes short action sequences in the _latent_ space (via the cross-entropy method / MPPI-style planning) using the learned model to score rollouts, and executes the first action of the best plan.|None by default. The latent state is a function of the current (and very recent) observation(s), not a persistent memory across the whole episode; planning is short-horizon.|Included as a strong, sample-efficient model-based baseline. Performs well on tasks solvable from local dynamics (e.g., simple interception), but shows the same collapse as SAC-MLP once the task needs information from many steps earlier than the current planning horizon covers.|

_Evaluation setup:_ `RGB+joints` observation mode (two camera views + joint states — the paper's designated standard memory-testing configuration), both dense and sparse reward variants; 3 independent training runs, each evaluated over 16 episodes, results as mean ± SEM.

### Offline RL Baselines

|Approach|Architecture & How It Works|Memory Mechanism|Role / Results in Paper|
|---|---|---|---|
|**BC (Behavioral Cloning)**|Pure supervised learning: an MLP is trained to directly regress the expert action given the current observation, using the offline dataset as (observation, action) pairs with no reward signal or bootstrapping at all.|None. Purely reactive mapping from current frame to action.|Simplest possible imitation baseline. Performs near BC-floor on all but the easiest tasks, and at 0.00 on every Sequential/Capacity task, since it cannot condition on anything beyond the current frame.|
|**CQL (Conservative Q-Learning)**|An offline actor-critic method that trains Q-functions with a standard Bellman/TD objective _plus_ a conservative penalty term that pushes down Q-values for actions not seen in the dataset (and pushes up Q-values for the actual dataset actions). This counteracts the value overestimation that off-policy algorithms suffer when trained purely offline (no ability to correct via new environment interaction). Built on an MLP backbone.|None. Same current-observation-only limitation as BC.|Classic offline-RL baseline representing "value-based" methods without any sequence modeling; fails similarly to BC on memory-heavy tasks.|
|**DT (Decision Transformer)**|Reframes RL as sequence modeling: a causal (GPT-style) Transformer is trained via next-token-style supervised prediction over sequences of (return-to-go, state, action) triples. At inference, the desired return-to-go is specified and the model autoregressively predicts the next action conditioned on the whole trajectory prefix seen so far. The self-attention mechanism lets each predicted action attend to _all_ previous tokens in the context window.|Implicit, via self-attention over the trajectory history held in the context window (no dedicated memory module; capacity is bounded by context length).|A sequence-model baseline without dedicated memory machinery. Does better than BC/CQL on some Intercept tasks (where the trajectory itself carries the needed velocity information) but still fails on RememberColor5/9 and all Sequential/Capacity tasks, where the relevant cue is far outside a useful attention pattern or gets diluted.|
|**RATE (Recurrent Action Transformer with Memory)**|Extends the Decision-Transformer-style sequence model by adding an explicit recurrent memory component alongside the Transformer's attention: past context is periodically compressed into a persistent memory state that is carried forward and made available to the Transformer at future steps, rather than relying solely on however much raw history fits in the attention window. This lets the model retain information from far outside its immediate context.|Explicit — dedicated recurrent memory state combined with Transformer attention.|The strongest offline baseline in the paper (e.g., 0.92 SR on ShellGameTouch, 0.65 on RememberColor3), demonstrating that adding explicit memory to a sequence model meaningfully helps — but it still scores 0.00 on all BunchOfColors/SeqOfColors/ChainOfColors tasks, showing its memory still can't handle the highest Capacity/Sequential loads.|
|**DP (Diffusion Policy)**|Models the action-generation process as a conditional denoising diffusion model: given the current observation(s), the policy learns to iteratively refine a noisy action (or short action-chunk) into a clean one over several denoising steps, trained with the standard diffusion loss on expert trajectories. Popular in manipulation because it captures multimodal action distributions well.|None inherent — reward/observation conditioning is local; any implicit temporal information comes only from action chunking, not persistent memory.|A strong manipulation-specific baseline (e.g., 0.68 on InterceptMedium — the best of the five there), but weak on tasks requiring true recall across an occlusion, since it has no mechanism to store information from earlier in the episode.|
|**DMamba** _(Appendix J)_|Applies the Mamba/S6 state-space-model architecture (selective, input-dependent state transitions computed via a hardware-efficient scan) to the Decision-Transformer sequence-modeling setup, replacing self-attention with a linear-time recurrent SSM layer.|Implicit, via the SSM's persistent hidden state that is selectively updated (input-dependent gating) as it scans through the trajectory.|Improves over plain DT/BC by being able to propagate information more efficiently over longer sequences than fixed-window attention, but still trails RATE, particularly on RememberColor5/9.|
|**GTrXL** _(Appendix J)_|Gated Transformer-XL: augments a Transformer-XL (which reuses cached hidden states from previous segments to extend effective context beyond one window) with gating mechanisms (similar in spirit to LSTM gates) applied to the residual connections around attention and feedforward sublayers, which stabilizes training and lets the network learn to combine current and past-segment information more reliably.|Explicit — segment-level memory reuse (Transformer-XL) plus learned gating for controlled information flow.|The best non-RATE performer in the appendix ablation, confirming that adding recurrence/gating on top of attention consistently helps versus vanilla DT, though it still falls short of RATE's dedicated memory design on the hardest memory tasks.|

_Evaluation setup:_ Trained on 1,000 expert trajectories per task (RGB mode: two camera views; sparse/success-only reward); 3 runs × 100 eval episodes, mean ± SEM.

### VLA (Vision-Language-Action) Baselines

|Model|Architecture & How It Works|Memory Mechanism|Role / Results in Paper|
|---|---|---|---|
|**Octo**|A generalist transformer policy pretrained across many robots/tasks in the Open X-Embodiment dataset. It tokenizes a fixed window of past observations/language/proprioception (context length 10 in this paper) into a shared transformer backbone, and uses lightweight diffusion "action head" modules attached to the transformer's outputs to produce continuous action chunks (chunk size K=4 here). Only the readout/action heads were fine-tuned per task in this paper, keeping the large pretrained backbone frozen.|Implicit, bounded to whatever fits in the fixed 10-step context window; no persistent state beyond that.|Shows some innate memory capacity on simple tasks (better than random) because the occlusion gaps happen to fit within its 10-step context, but degrades sharply as task complexity/gap length grows beyond that window.|
|**OpenVLA**|Built on a Prismatic-7B vision-language backbone (a VLM combining vision encoders with a language model), fine-tuned here with LoRA adapters (low-rank update matrices injected into the frozen backbone's weights, drastically reducing trainable parameters) and an L1 regression loss on action chunks. Two chunk sizes are tested: K=4 and K=8 (i.e., predicting 4 or 8 future actions per forward pass).|None explicit — no persistent hidden state across steps; whatever "memory" exists is an artifact of how large an action chunk is predicted from a single observation.|With K=8, larger action chunks let the model implicitly encode more of the required plan into one shot, so it exceeds random performance on RememberColor3/ShellGameTouch despite no step-wise history; with K=4 it performs close to random, showing chunking — not real memory — drives the K=8 gains.|
|**SpatialVLA**|A VLA that augments the standard vision-language-action pipeline with explicit egocentric 3D positional encodings (giving the model a stronger geometric/spatial prior) and discretizes the continuous action space into a grid for classification-style prediction instead of regression. Evaluated at chunk size K=4.|None explicit for temporal memory (the 3D encodings help spatial reasoning within a single observation, not recall across occlusion).|Comparable to π0 on easier spatial tasks (benefiting from its 3D positional priors) but, like the other K=4 models, fails once the task truly requires bridging an occluded interval.|
|**π0**|Combines a pretrained vision-language model with a lightweight "flow-matching" action expert: a small network trained via flow-matching (a continuous-normalizing-flow-style generative objective, related to diffusion but often faster to sample) to produce continuous action trajectories conditioned on the VLM's representation of the current observation and instruction. Evaluated at K=4.|None explicit.|The best of the K=4 models on Intercept tasks (where recent velocity cues are still in view), but fails to scale to higher-complexity RememberColor variants, consistent with having no persistent memory.|
|**π0.5**|The successor to π0, used only in the real-world SO-101 experiments (not in the simulated Table 4 comparison). Same general VLM + flow-matching-expert design philosophy, generalized further and fine-tuned per real-world task in this paper (100,000 gradient steps per stage) rather than evaluated zero-shot.|None explicit for long-horizon recall.|Real-world results mirror the simulated pattern precisely: near-perfect on the fully observable sanity-check task, degraded under dynamic-but-unoccluded change, and near-failure once genuine occlusion + permutation (true memory) is required — reproducing the simulation hierarchy physically.|
