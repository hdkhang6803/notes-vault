# 1. Terminology

| Term                                | Definition                                                                                                                                                                                          |
| ----------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **GUI Agent**                       | An autonomous system that perceives and interacts with Graphical User Interfaces (mobile apps, websites, desktop software) to complete user-specified tasks.                                        |
| **SE-GA**                           | Self-Evolving GUI Agent: the proposed framework combining hierarchical memory with iterative self-improvement for GUI navigation.                                                                   |
| **TTME**                            | Test-Time Memory Extension: a hierarchical retrieval module that manages episodic, semantic, and experiential memory at inference time to extend effective context beyond the model's fixed window. |
| **MASE**                            | Memory-Augmented Self-Evolution: a two-stage training pipeline (Grounding Training + Self-Evolution Training) that converts accumulated memories into improved policy parameters.                   |
| **POMDP**                           | Partially Observable Markov Decision Process: the formal model used to capture GUI navigation under partial observability (occluded info, layout changes, system latency).                          |
| **Episodic Memory ($M^{EPI}$)**     | Short-term working memory recording recent ⟨state, action, next-state⟩ transitions within a sliding window for the current task.                                                                    |
| **Semantic Memory ($M^{SEM}$)**     | Long-term repository of abstract, domain-general interaction rules (e.g., "log in before accessing restricted pages"), indexed by embedding.                                                        |
| **Experiential Memory ($M^{EXP}$)** | Repository of reflective summaries distilled from previously completed tasks, enabling reuse of successful multi-step strategies.                                                                   |
| **HGS**                             | Hindsight Goal-Shifting: a data augmentation strategy that relabels failed trajectory prefixes as successful completions of reachable sub-goals, converting failures into usable training signal.   |
| **GRPO**                            | Group Relative Policy Optimization: the RL algorithm used in Stage II, extended with token-level importance ratios and adaptive clipping for stable GUI training.                                   |
| **VLM**                             | Vision-Language Model: the underlying multimodal backbone (Qwen2.5-VL-7B) that SE-GA fine-tunes and augments with memory.                                                                           |
| **Long-horizon task**               | A GUI navigation task requiring many sequential steps (16–47+ in this paper) across potentially multiple applications.                                                                              |
| **SFT**                             | Supervised Fine-Tuning: Stage I of MASE, where the model is trained via behavior cloning on memory-augmented expert trajectories.                                                                   |
| **Grounding Accuracy**              | Evaluation metric counting a prediction correct if the predicted coordinate lies inside the ground-truth bounding box, or IoU exceeds a threshold for scroll tasks.                                 |

# 2. Paper Summary (What)

SE-GA is a framework for autonomous GUI agents that combines a hierarchical memory system with a self-improving training loop. The core idea is organizing agent's interaction history into three distinct memory stores and then using that accumulated experience to continuously sharpen the agent's policy.

The framework consists of two tightly coupled components. 
- **TTME** handles inference time: it retrieves the right memories (recent history, general rules, and past task strategies) and injects them into the agent's context at each decision step. 
- **MASE** handles training time: it collects interaction data generated by TTME, applies Hindsight Goal-Shifting to maximize usable signal, and trains the agent in two stages: first with supervised grounding, then with RL-based self-evolution. 
Together they enable the agent to evolve from a static policy executor into a continual learner that improves with each deployment round.

---

# 3. What It Solves (Why)

- Error accumulation: Existing GUI agents rely on a fixed context window and the current screenshot, losing critical early-step information in multi-step tasks
- Current agents train on fixed datasets or perform temporary retrieval without unified memory organization => cannot extract reusable strategies from past successes, forcing them to re-solve identical subproblems from scratch in every new session.

# 4. Methodology (How)

> **Running Example:** Task: _"Using BBC Sports, find out when the next MLB game is scheduled, then create a reminder in Microsoft To-Do."_ 
## 4.1. System / Memory Structure

TTME maintains a three-tier repository $M = (M^{EPI}, M^{SEM}, M^{EXP})$ populated during task execution:

| Memory Type              | Role                                                              | Structure                                                                                                                                                                 |
| ------------------------ | ----------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Episodic (M^EPI)**     | Short-term working memory for the current task                    | Sliding-window log of recent ⟨state, action, next-state⟩ triples; window horizon H discards stale history                                                                 |
| **Semantic (M^SEM)**     | Persistent store of abstract interaction rules                    | Each entry: text description `d_i` + embedding key `k^sem_i`; retrieved by cosine similarity to instruction Q                                                             |
| **Experiential (M^EXP)** | Library of reflective summaries from past successful trajectories | Each entry: raw trajectory `τ_i`, reflective summary `g(τ_i)`, intent key `k^intent_i`, visual key `k^task_i`; retrieved by weighted hybrid of intent + visual similarity |

## 4.2. Retrieval Flow (Inference)

At each step _t_, the agent receives observation `o_t` (current screenshot) and instruction `Q`. TTME assembles `M_retrieved = (C^epi, C^sem, C^exp)` and passes it alongside the screenshot to the VLM policy.

**Example — Step 6 of the MLB task (agent is on BBC Sports, navigating toward the schedule)**

1. **Episodic context C^epi**: The sliding window returns steps 1–5 showing the agent opened BBC Sports, navigated to "Scores & Fixtures", clicked "A to Z", and arrived at a sport-category listing.
    
    - _Effect:_ Agent knows it is already inside BBC Sports, preventing redundant re-navigation back to the home screen.
2. **Semantic context C^sem**: Top-K rules retrieved by cosine similarity to Q = _"find MLB schedule"_. Example rule returned: _"Sports listings on BBC are indexed alphabetically; scroll to the letter of the sport before searching."_
    
    - _Effect:_ Agent understands the A-to-Z listing structure and knows to look under "B" (Baseball/MLB).
3. **Experiential context C^exp**: Hybrid retrieval (intent + visual similarity) surfaces a past trajectory summary: _"For BBC Sports schedule tasks, tapping the search icon and typing the league acronym is faster than alphabetic browsing."_
    
    - _Effect:_ Agent pivots to the faster search-icon strategy — step 9: click search icon `[775, 116]`; step 11: type "MLB".
4. **Action decision**: Policy `π_θ(a_t | o_t, Q, M_retrieved)` generates `CLICK [775, 116]`, informed jointly by all three memory types.
    

## 4.3. Updating Flow (MASE Training)

After interaction rounds, trajectories stored by TTME feed MASE's two-stage pipeline:

**Step 1 — Hindsight Goal-Shifting (HGS)** The full 13-step trajectory fails at step 13 (To-Do reminder creation incomplete). However, the prefix steps 1–12 successfully locate the MLB schedule on BBC Sports. HGS relabels this prefix with the sub-goal _"Find the next MLB game date using BBC Sports"_ and adds it to D^GS as a positive training example.

- _Effect:_ A failed trajectory becomes valid supervision for a well-defined sub-task.

**Step 2 — Stage I: Grounding Training (SFT)** The relabeled sample, together with 2K curated trajectories from D^ground, trains the VLM via memory-aware behavior cloning (negative log-likelihood over expert actions). The model learns to correctly identify and click GUI elements like the BBC Sports search icon given the full memory context.

- _Effect:_ Prevents catastrophic forgetting and anchors the agent's spatial grounding ability.

**Step 3 — Stage II: Self-Evolution Training (GRPO)** The agent samples G=16 action rollouts from the MLB sub-task prompt. A hierarchical reward scores each rollout: `R_format` checks JSON validity; `R_acc` checks point localization (click lands inside target bounding box) or exact action-type match. Group-normalized advantages A_i update LoRA parameters via token-level importance ratios with cosine-decayed adaptive clipping to prevent policy collapse.

- _Effect:_ The refined policy reliably executes the BBC Sports search sub-task; the successful trajectory is written back into M^EXP for future retrieval.

## 5.3. Notable Results

- SE-GA (7B) surpasses UI-TARS (72B) on AndroidControl-High and GUIOdyssey — roughly 10× fewer parameters with better or comparable performance.

- Continual self-evolution over 3 rounds yields monotonic gains on every benchmark, with the largest absolute gains on long-horizon tasks (GUIOdyssey: 52.3% → 83.9%).

# 6. Strengths

- **Complementary module design**: TTME and MASE address orthogonal failure modes — context loss (inference) and static policy (training). Ablations confirm both are necessary; removing TTME costs 12.4% SR on AC-High, removing MASE costs ~14%.
- **Self-improvement without human annotation**: HGS converts failed trajectories into valid sub-task demonstrations automatically, removing the manual labeling bottleneck.
- **Online evolution at inference time**: TTME accumulates new successful trajectories in real time during deployment, enabling improvement even between training rounds.
- **Training stability**: Token-level importance ratios + cosine-decayed adaptive clipping address GRPO's known instability on sparse-reward, long-horizon tasks.
- **Cross-scale competitiveness**: A 7B model consistently beats or matches 72B baselines, suggesting the memory framework adds more capability than raw scale alone.

---

# 7. Gaps

- **Memory retrieval latency**: As M^EXP grows, embedding-similarity and visual-feature retrieval introduce increasing overhead, potentially bottlenecking latency-sensitive deployments. _Future direction: approximate nearest-neighbor indexing (e.g., HNSW) or learned compression of experiential entries._
- **Small training corpus**: MASE uses only 4K trajectories, which may not represent the diversity of real-world GUI environments. The Round 2→3 performance slowdown hints at diminishing returns from memory saturation. _Future direction: scale corpus and study the saturation curve._
- **No explicit sub-goal planning**: The agent plans end-to-end without a task decomposition layer, causing instability on 30+ step workflows (visible in Figure 6). _Future direction: a high-level planner that decomposes instructions into sub-goals each handled by TTME retrieval._
- **Platform specificity**: All evaluations are Android-only; transfer to web and desktop GUIs is assumed but untested. _Future direction: cross-platform evaluation and investigation of whether experiential memories transfer across platform boundaries._
- **Memory staleness**: No mechanism exists to detect or prune experiential memories made incorrect by app updates or layout redesigns. _Future direction: a memory validity module that invalidates entries when visual similarity to recent observations drops below a threshold._
